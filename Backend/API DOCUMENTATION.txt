## AUTH API DOCUMENTATION ##
---------------------------------

Base URL

http://localhost:8080/api/auth

---

1. Health Check

GET /health

Response

{
"success": true,
"message": "server is running properly"
}

---

2. Signup

POST /signup

Body

{
"name": "Adarsh",
"email": "[adarsh@gmail.com](mailto:adarsh@gmail.com)",
"password": "12345678",
"phoneNumber": "9876543210"
}

Success Response

{
"success": true,
"message": "OTP sent successfully",
"email": "[adarsh@gmail.com](mailto:adarsh@gmail.com)"
}

---

3. Verify OTP

POST /verify-otp

Body

{
"email": "[adarsh@gmail.com](mailto:adarsh@gmail.com)",
"otp": "123456"
}

Success Response

{
"success": true,
"message": "Account verified successfully"
}

---

4. User Login

POST /login

Body

{
"phoneNumber": "9876543210",
"password": "12345678"
}

Success Response

{
"success": true,
"message": "Login successful",
"token": "JWT_TOKEN",
"user": {
"id": "USER_ID",
"name": "Adarsh",
"email": "[adarsh@gmail.com](mailto:adarsh@gmail.com)",
"phoneNumber": "9876543210",
"verified": true,
"isAdmin": false
}
}

---

5. Admin Login

POST /login

Body

{
"phoneNumber": "9876543210",
"password": "12345678",
"adminPassKey": "ADMIN_SECRET_KEY"
}

Success Response

{
"success": true,
"message": "Login successful",
"token": "JWT_TOKEN",
"user": {
"isAdmin": true
}
}

---

Validation Rules

Email: Valid email format

Phone Number: 10 digit Indian number

Password: Minimum 6 characters

OTP: 6 digits

---

User Flow

Signup → Receive OTP → Verify OTP → Login

Admin Login

Login + Correct Admin Pass Key → isAdmin = true

TRAFFIC MANAGEMENT API DOCUMENTATION
========================================

Base URL:
http://localhost:5000/api/traffic

----------------------------------------
1. CREATE SIGNAL
----------------------------------------

Method:
POST /create

Request Body:

{
  "signalNumber": "SIG001",
  "roadName": "NH24",
  "latitude": 28.6139,
  "longitude": 77.2090,
  "cameraNumber": "CAM001",
  "roadWidth": 20,
  "currentVehicleCount": 45,
  "currentRedLightTime": 40,
  "currentGreenLightTime": 30,
  "vehicleDensity": 0.65,
  "congestionLevel": "MEDIUM"
}

Response:

{
  "success": true,
  "data": { ...signalData }
}

----------------------------------------
2. UPDATE TRAFFIC DATA
----------------------------------------

Method:
PUT /update/:signalNumber

Example:
PUT /update/SIG001

Request Body:

{
  "currentVehicleCount": 60,
  "currentRedLightTime": 55,
  "currentGreenLightTime": 45,
  "vehicleDensity": 0.82,
  "congestionLevel": "HIGH"
}

Response:

{
  "success": true,
  "data": { ...updatedSignalData }
}

Note:
Previous values are automatically moved to:
- lastVehicleCount
- lastRedLightTime
- lastGreenLightTime

----------------------------------------
3. GET SIGNALS BY ROAD NAME
----------------------------------------

Method:
GET /road/:roadName

Example:
GET /road/NH24

Response:

{
  "success": true,
  "count": 2,
  "data": [ ...signals ]
}

----------------------------------------
4. HEALTH CHECK
----------------------------------------

Method:
GET /health

Response:

{
  "success": true,
  "message": "server is running properly"
}

# Complaint Management API Documentation

Base URL

http://localhost:8080/api/complaints

---

1. Add Complaint

Endpoint:
POST /add

Headers:
Authorization: Bearer <JWT_TOKEN>

Body (form-data):

category       (Text)
description    (Text)
location       (Text)
images         (File, Optional)

Example:

category: Potholes
description: Large pothole causing traffic congestion near metro station
location: Sector 62 Metro Station, Noida
images: pothole.jpg

Success Response:

{
"success": true,
"message": "Complaint added successfully",
"complaint": {
"_id": "complaintId",
"category": "Potholes",
"status": "Pending"
}
}

---

2. Get All Complaints

Endpoint:
GET /all

Headers:
None

Success Response:

{
"success": true,
"count": 2,
"complaints": [...]
}

---

3. Get My Complaints

Endpoint:
GET /user/my-complaints

Headers:
Authorization: Bearer <JWT_TOKEN>

Success Response:

{
"success": true,
"complaints": [...]
}

---

4. Get Single Complaint

Endpoint:
GET /:id

Example:

GET /6a2e50a30bac3605f8b006f1

Success Response:

{
"success": true,
"complaint": {
"_id": "6a2e50a30bac3605f8b006f1",
"category": "Potholes",
"description": "...",
"location": "...",
"status": "Pending"
}
}

---

5. Upvote Complaint

Endpoint:
POST /upvote/:id

Headers:
Authorization: Bearer <JWT_TOKEN>

Success Response:

{
"success": true,
"message": "Upvote added",
"upvotes": 1
}

Error Response:

{
"success": false,
"message": "Already upvoted"
}

---

6. Remove Upvote

Endpoint:
POST /remove-upvote/:id

Headers:
Authorization: Bearer <JWT_TOKEN>

Success Response:

{
"success": true,
"message": "Upvote removed",
"upvotes": 0
}

---

7. Mark Complaint In Progress

Endpoint:
PUT /in-progress/:id

Headers:
Authorization: Bearer <ADMIN_TOKEN>

Success Response:

{
"success": true,
"message": "Complaint marked as In Progress"
}

---

8. Resolve Complaint

Endpoint:
PUT /resolve/:id

Headers:
Authorization: Bearer <ADMIN_TOKEN>

Body (raw JSON):

{
"comment": "Road repaired successfully"
}

Success Response:

{
"success": true,
"message": "Complaint resolved successfully"
}

---

9. Delete Complaint

Endpoint:
DELETE /:id

Headers:
Authorization: Bearer <JWT_TOKEN>

Success Response:

{
"success": true,
"message": "Complaint deleted successfully"
}

---

Complaint Status Values

Pending
In Progress
Resolved

---

Complaint Categories

Traffic Jam
Potholes
Water Logging
Broken Signals
Encroachment
Others

---

{
"success": false,
"message": "Invalid token"
}

403 Forbidden

{
"success": false,
"message": "Not authorized"
}

404 Not Found

{
"success": false,
"message": "Complaint not found"
}

{
"success": false,
"message": "Server error"
